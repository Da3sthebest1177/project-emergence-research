# Project Emergence Autonomous Research Lab v2.4 — Approval-gated development

## Existing project preserved

The GitHub automation retains the v2.3.1 research runner and both stress suites, and does not contain or overwrite the repository's `data/` research history. The prior 9 saved research cycles should remain intact after this upgrade.

## What this new release does

1. Runs an optional AI-assisted development proposal after each research cycle, when the `EMERGENCE_DEV_ENABLED` repository variable is set to `true`.
2. The AI chooses **only validated settings from preimplemented memory policies** (`fifo`, `salience`, `novelty`) and **attention policies** (`goal_recency`, `goal_salience`, `goal_diversity`), alongside bounded capacity settings. There is no ability to provide arbitrary executable code.
3. A trusted template generates the reviewable candidate file `proposals/active_candidate.py`; controlled synthetic comparisons and a report are saved alongside it.
4. GitHub opens or updates a draft pull request; the main branch is not modified by the proposal. Its contents must be manually reviewed.
5. The existing AI Critic's strict structured-output request can fall back to JSON Object mode when Groq returns HTTP 400. This addresses one *possible* cause of Cycle 9's `Critic unavailable: HTTP 400`, without claiming all HTTP 400s are resolvable.

## What it does NOT do

- No continuous runtime: GitHub runs scheduled jobs rather than a 24/7 process.
- This ChatGPT conversation does not run in the background.
- No general open-ended code rewriting. The generated Python module is an allowlisted template, not model-authored source.
- No automatic merging, self-deployment, spending, independent browsing, or consciousness claims.
- No AI API when a key is absent (deterministic fallback is explicitly labeled).

## Manual setup needed once

1. Upload `emergence-lab.zip` at the root of `project-emergence-research`.
2. Upload the provided `install-emergence.yml` to the existing `.github/workflows/` folder, replacing the old file. This must be a manual change; the installer is not authorized to modify GitHub workflows.
3. Enable **Allow GitHub Actions to create and approve pull requests** in repository Settings → Actions → General → Workflow permissions.
4. Under Settings → Secrets and variables → Actions → Variables, add `EMERGENCE_DEV_ENABLED` with value `true`. Do not share or upload any API secrets.
5. Under Actions, run **Project Emergence - Research and Development**. The development job should generate a draft pull request, typically titled **Project Emergence: AI-reviewed candidate experiment**.

# Project Emergence — Autonomous Development Pipeline v2.4

This upgrade adds a bounded AI-assisted experimental development loop to the established daily research cycle. The Lab's main branch remains human-controlled. No code or secret may be generated by an LLM and executed directly.

## Setup (one-time, phone-friendly)

1. Upload `emergence-lab.zip` to the GitHub repository's root, commit. Do **not** upload the whole repository ZIP.
2. Open `.github/workflows/install-emergence.yml`, edit its contents and replace with the complete `emergence-autodev-workflow.yml` supplied alongside the package. Commit this edit manually. This one-time replacement is needed because GitHub does not let the existing automation rewrite workflow files.
3. In GitHub **Settings → Actions → General → Workflow permissions**, enable **Allow GitHub Actions to create and approve pull requests** and save. This setting permits the token to create a PR; the workflow itself never approves/merges PRs.
4. In **Settings → Secrets and variables → Actions → Variables**, add `EMERGENCE_DEV_ENABLED` = `true`. Keep `EMERGENCE_API_KEY` secret and existing model variables unchanged.
5. Open **Actions → Project Emergence - Research and Development → Run workflow**.
6. Read the run status. On success, look under **Pull requests** for the **draft** PR. It contains a proposed policy, held-out synthetic measurements, and limitations. Do not merge blindly.

## What runs unattended

- Daily bounded research cycle, reports and persistent history (existing behavior).
- A scheduled experimental-development candidate generated from an allowlisted policy design (API when available, explicitly labelled fallback when not).
- Evaluation of candidate versus original workspace with same-seed synthetic tests.
- Regression checks; a **draft pull request** for human inspection; never an unattended merge.

## Important scientific limitations

This **does not give this ChatGPT conversation background access**. The separate Groq-hosted model is used for proposals. The generated candidate is made using an allowlisted Python template with validated settings. The broader software architecture is not being autonomously rewritten: it explores only a set of explicitly supported memory and attention algorithms. This is a safety and reliability boundary, and a real architectural research extension would still need review.

GitHub schedules are best-effort and may be delayed or disabled after repository inactivity. API free-tier limits may prevent some AI requests; the fallback will be labelled as deterministic. A pull request created with `GITHUB_TOKEN` does not automatically trigger ordinary checks in every workflow. The necessary tests are run in the same development job before opening the PR. This runner has not been tested with GitHub's actual PR permissions in this environment; its first live run confirms those.

## Troubleshooting

- **Red X at 'Create or update review-only pull request'**: check Settings → Actions → General → Workflow permissions; enabling the PR setting may be required.
- **Development job skipped**: make sure `EMERGENCE_DEV_ENABLED` is a repository **variable**, spelled exactly `true`.
- **Draft PR contains `deterministic fallback`**: Groq is unavailable or returned invalid output; check the job logs for a safe error type. Secret value must never appear in logs.
- **Research job succeeds but development fails**: research is preserved. No speculative code is merged automatically.
